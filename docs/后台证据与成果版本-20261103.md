# 后台处理证据、原任务补救与成果版本 · 2026-11-03

## 已确认范围

1. 会话内点击消息展开处理轨迹，不新增独立消息处理页面。展示真实接收、连续补充、本地整理、上下文/附件、记忆、模型、工具、资源等待和发送阶段。并行阶段不重复相加；未执行的阶段不称为成功。
2. 失败在原任务补救，保留失败及后续尝试。区分未完成、部分完成、文件已生成但发送失败、送达未确认、配置/账号问题。安全读取可自动补救一次；付费模型受理或发送不明确不自动重放。后台明确点击继续才会调用模型。
3. 保留成果、可用源文件、制作代码、素材与配方。允许围绕请求调整整份成果，保留明确事实与数据。默认最新版；引用旧版则从旧版分支。修改后直接交付新版本和简短说明，不等预览确认。各格式各自保留版本链，旧版不覆盖。
4. 后台显示候选、选入上下文、请求提交中、请求收到响应及未确认的记忆快照与来源。不能声称模型一定采纳。沿用编辑/删除，不加单轮排除重答。历史快照不随记忆更正/删除改写。
7. 独立报错日志，显示请求、任务、阶段、原因、保留成果与补救入口。相同根因合并次数、首次/最近时间；自动补救成功也保留。技术信息折叠并隐藏常见凭据。不弹窗、不发桌面通知，只显示后台未解决数量。忽略不等于修复。

多平台接入仍在待办，一键更新和回复形式不在本次范围。

## 实现归属

- diagnostics.py：ContextVar关联、处理阶段、记忆快照、根因日志及恢复证据。记录来自真实工作；没有主动探测、合成测试或额外模型调用。
- recovery.py：成功工具回执、原任务继续、只重发已有文件、同任务原子状态认领。重启不自动执行普通任务。环境可能已释放，从保留文件/代码恢复必要输入，不假设旧Python变量仍在。
- artifacts.py：成果系列、版本父节点、来源引用和制作配方。旧输出在实际修改时按需纳入版本；不能恢复已经清理的文件或不存在的源资料。
- agent.py/models.py/tasks.py/runtime.py/memory.py：在原调用边界接记录，不复制独立执行核心。既有账号、模型选择、用量和授权校验继续生效。
- diagnostics-ui.js/conversations.js：会话内详情、记忆来源定位、任务补救、版本与配方、后台报错日志。

新增SQLite表：requests、request_messages、request_spans、request_memories、faults、fault_occurrences、tool_receipts、deliveries、artifacts、artifact_versions。启动只增加表与索引，不删除旧记录。

## 边界与证据

- 新处理轨迹从更新后收到的消息开始，不伪造历史消息的模型/工具时间。已有旧任务的步骤和文件继续可见；旧成功工具结果仅按安全字面量读取，不eval、不重跑旧代码。
- 修改对象以引用成果为先；多个候选无法明确选择时交由模型结合真实文件清单询问，不随机挑文件。源信息不足不能宣称精确还原。
- “已随请求提供”依据文本标识与内容出现在请求中，并且调用返回响应；不是模型理解或采纳证明。
- 版本和依赖通过file_refs保留，内容地址去重；源文件下载仍按本地后台或原消息权限。
- 制作说明来自工具的change_summary；缺失时明示“修改要求”，不伪造内容差异检测。
- 一次读取自动重试只用于安全网页下载的临时故障；404/410仍允许原有一次替代有效来源的补救，不原址反复打。模型与写操作不作无条件自动重试。
- 重发不重新生成；送达未确认时必须由用户先核对并明确选择重发。使用原账号、会话和当前接入实际取得的目标，不恢复普通历史发送目标。
- “已恢复”是已有后续成功证据，原失败详情保留；忽略独立记录。没有新消息/任务就不会为了检测健康而调用模型。
