# 机器人重做：已确认需求与总体设计

更新日期：2026-11-01。

状态：需求讨论记录。尚未开始新版功能开发、UI 实现或测试。本文汇总用户已确认的方向；文末列出未定的数值和技术细节，不能将其当成已实现功能。

## 1. 项目目标和交付方式

- 一个 Windows 软件，整合 AstrBot 核心、QQ 接入、GPT 套餐桥和自定义功能。
- 复用 AstrBot 的基础能力，重整自定义模块和界面；不把旧插件整体原样打包。
- 新项目不考虑旧系统迁移或旧方案兼容。
- 同时提供桌面窗口和浏览器后台；浏览器仅本机访问，不开放局域网和公网入口。
- 两个入口连接同一个核心，共享配置、数据和布局。
- 登录 Windows 后自动启动并收进托盘；关闭窗口继续运行，明确退出才停止服务。
- 统一重做管理界面，日常管理不依赖 AstrBot 原后台。
- 安装时一次准备完整功能与依赖，统一显示准备进度和各模块就绪状态。
- 12 类功能全部完成后，由用户逐项检查验收；不安排分阶段验收。目前不开发、不运行测试。
- 第一版实际运行一个机器人账号，但账号、连接、任务和数据保留机器人身份维度，为多账号预留结构。
- 多账号的人格、记忆和额度共享方式尚未确定，第一版不额外实现多账号运行。

## 2. 总体组织原则

这是已确认方向所要求的职责划分，不是具体技术栈选型：

1. 主程序统一管理窗口、后台服务、配置、更新和生命周期。
2. QQ 接入负责指定机器人账号的收发与连接；模型桥负责 GPT 套餐接入。
3. AstrBot 提供消息处理、模型与插件基础机制。
4. 聊天、记忆、任务、文件、用量、发送分别有明确负责人，公共能力集中实现。
5. 耗时工作按步骤调度，重型模型和代码执行使用可独立管理的执行环境。
6. 通过接口、适配层和集中维护的必要改动组织扩展，减少零散运行时补丁。
7. 有自主能力不等于无目的执行。主动参与以文字交流为主，工具服务于实际目的。

## 3. 聊天体验与人格

### 3.1 表达和接话

- 闲聊、任务处理和错误说明保持统一人格，不自动切换成另一套工作人格。
- 用户明确指定的文档格式、公式和准确性要求仍然满足。
- 人格说明可在应用里编辑。
- 默认短暂等待同一用户、同一会话的连续补充，合起来理解。
- 应用可改成每条立即处理；等待时长与最长等待可调。
- 默认根据回复期间收到的新消息调整：纠正、补充、打断会停止尚未发出的过时内容，独立问题另行处理。
- 应用可改成先答完再处理新消息。已发出的气泡保留。
- 取消、停止指令优先处理。

### 3.2 自主人格成长

- 允许机器人自主修改人格并直接生效，不逐次请求管理员批准。
- 希望它有个性、有主见，不轻易被一句话或多人附和改变，同时保留成长性。
- 表达习惯较容易调整；观点与关系结合证据更新；核心性格保持较强连续性。
- 事实纠错及时处理；适应某个人的表达偏好不等于重写整个人格。
- 保留修改原因、相关经历、前后版本，应用支持查看、编辑和恢复。
- 人格不能自行覆盖管理员明确锁定的软件规则。

### 3.3 成长触发与可视化

- 仅在机器人核心启动时检查人格成长；打开窗口、打开浏览器页面不重复触发。
- 连续运行期间只积累经历，不按天、不按消息次数自动复盘。
- 只处理上次复盘之后的新增经历；没有新增经历则跳过，没有实质变化则不生成总结或修改人格。
- 后台处理，不阻塞登录和正常聊天。
- 应用展示当前人格、变化曲线、成长时间线和版本对比。
- 曲线是对人格文本的近似描述，不是客观心理测量；没有变化就保持原值，不编造波动。
- 日常记忆维护与人格启动复盘是两套触发机制，不能将记忆更新也延迟到下次启动。

## 4. 群聊和会话边界

- 群内可以读取未 @机器人的普通消息，是否记住、是否回复分别判断。
- 只处理接入端实际收到的消息，不能声称拥有未获取的历史。
- 群记忆共享，当前讨论按话题组织，避免把同时发生的不同话题混成一条对话。
- 保留实际账号、昵称、时间、群、引用关系；昵称不是身份依据。
- 引用确定话题，再结合该话题的后续更新、有效期和相关记忆回答。
- 机器人可以在群里主动参与并 @相关成员。
- 默认只在有新消息时参与；应用可逐群开启冷场后主动发起话题。
- 主动发言频率、冷场时长、免打扰时段可配置。
- 私聊不主动发起闲聊；用户明确交代的通知和指定管理员的管理通知按授权处理。

## 5. 统一记忆

### 5.1 存储、来源与共享

- 所有记忆由一套系统管理，不按聊天窗口拆成互不相通的脑子。
- 记忆保留人物、实际发言人、场合、时间、原始证据、信息性质、更新关系和使用限制。
- 转述、玩笑、推测、本人自述不能混成同一种确定事实。
- 公共知识可跨用户、跨会话复用，例如地区一致、仍适用的优惠资料。
- 优惠等动态信息保留来源、适用地区、有效期和核实时间，过期或需要最新信息时更新。
- 个人偏好仍属于对应的人，不能套到其他用户身上。
- 私聊个人事情不主动向群里传播、接梗或替别人联络。
- 本人在群里提问时，可使用其私聊偏好改善回答，不主动交代私聊来源。
- 明确的保密和使用范围要求需要随记忆及派生摘要传递。

### 5.2 分工和检索

- 程序记录身份、时间、引用和归属。
- 本地小模型增量整理话题、事实候选、偏好、事件、重复内容和冲突，辅助筛选相关记录。
- 检索系统同时保留原文证据入口，不能只靠小模型提炼出的结论。
- 最终对话由统一主模型完成，必要时在正常对话中纠正记忆。
- 小模型不直接代替主模型回答普通消息。
- 不为每句消息额外开启一次云端记忆反思；不把所有历史反复传给主模型。
- 本地辅助模型具体型号以后按实际任务表现选择，目前不指定最终型号。

### 5.3 修改、删除和遗忘

- 用户可以查看、修改、删除自己提供的记忆，权限由程序核对账号与来源。
- 用户不能改写、删除别人的发言；可补充自己的反驳与纠正，保留不同来源。
- 普通删除直接移除选中的记忆及对应索引，不设置禁止重新学习标记。
- 原始聊天和文件不因删除一条记忆而自动删除；后续遇到相关内容或重新整理原文，可以重新学会。
- 允许自主遗忘：降低过期、重复、低价值内容的检索优先级，确认无保留价值后清理。
- 失效信息可能仍有历史用途，不能一律删除；稳定偏好、重要经历及有依赖的记忆谨慎处理。
- 普通原始消息定期清理，重要记忆所引用的原消息保留。

## 6. 模型、强度和节省消耗

- 管理员全局选择一个对话主模型，所有用户和任务使用它，不自动更换主模型。
- GPT 通过套餐桥接入；其他提供商通过统一模型接入层使用。
- 任务开始时固定主模型和相关配置；后续切换影响新请求。
- 每个模型独立保存思考强度设置，应用可选固定或自动模式。
- 自动模式只使用该模型实际支持的强度，允许范围可配，优先复用本地判断。
- 按需加载工具、检索相关记忆、复用识图结果、文档笔记和中间产物。
- 确定性的状态、发送结果和工具完成通知可由程序直接交付，无须再问主模型。
- 多人提出实质相同、允许共享的请求时，合并执行并复用结果；个人资料、私有文件和不同要求分别处理。
- 实际调用只记录一次，不重复计算消耗；明确要求重新生成时绕过旧产物复用。
- 不设置每次输入的固定 token 预算。

## 7. 自主权、任务调度与协作

### 7.1 自主执行

- 允许机器人主动调用全部已启用工具。
- 主动参与尽量只发文字；可以后台搜索、计算和查记忆，再整理成消息。
- 不为了展示能力主动制作或发送附件。确有必要时可自主生成文件、自行规划，无需大纲确认，使用公共额度。
- 自主产物是否发送，要结合当前话题；可以保存后暂不发。
- 自主工作遇到重复错误、没有进展或目标失效时主动收手。
- 另设整项任务的尝试次数、总时长、累计用量上限；按任务类型在应用里配置。

### 7.2 调度和修复

- 耗时任务与普通聊天独立处理，同一任务按步骤执行，不相关任务按资源条件并行。
- 用户明确任务优先于自主任务尚未执行的步骤。
- 已开始、不能安全中断的步骤先安全结束，再安排用户任务；其余自主步骤可等待或放弃。
- 图形、网络、模型、CPU 等资源分别调度，不让单个任务占住整个机器人。
- 允许自主分析错误、修改代码、调整参数、替换素材，复用已完成部分，只重做受影响步骤。
- 文件已生成但发送失败时保留文件，不能通过重新生成代替重发。
- 额度不足时结束本次任务，保留已有结果；额度恢复后不自动续跑，由用户主动要求继续。

### 7.3 协作授权

- 别人修改或取消任务，必须得到任务创建者同意。
- 创建者可对协作者一次授权，并限定操作范围；范围内不逐次询问。
- 授权仅对这一次任务有效，可撤销；下一次任务重新授权。
- 普通讨论、引用消息不等于获得任务控制权。
- 区分发言人、任务创建者、协作者、提醒对象。
- 群任务的授权请求在原群 @创建者，不主动私聊征询。

### 7.4 中断和报告

- 软件停止、崩溃后，以及确认 QQ 断联后，所有未完成任务中断。
- 范围包括执行中、排队、尚未到期提醒和周期安排。
- 重启或重连后不恢复、不补发旧任务，只接新任务。
- 保留任务历史、阶段、原因和已有产物，不因中断删除记忆。
- 对外部已受理操作尝试取消，无法确认实际结束的要记录真实状态，不能假装已撤回。
- 中断汇总仅通过 QQ 私聊指定管理员报告，不往原群或普通用户私聊发送。
- QQ 未连接时先保留报告，恢复后合并发送。

## 8. 文件和各类工具

### 8.1 文件生命周期

- 区分原件、最终产物、中间文件、可复用素材和运行缓存。
- 保存来源、归属、生成代码、任务关系及实际依赖，支持找回、重发和继续处理。
- 正在使用、已收藏、明确保留、发送失败待交付、重要记忆需要的文件受保留规则保护。
- 先清理无用临时文件、中间产物和可重新获取的缓存；普通文件按期限清理。
- 大原件被重要记忆引用时，默认长期保留相关证据及必要上下文；完整原件按普通期限管理，收藏或仍有任务依赖时继续保存。
- 明确记录保留的是完整原件还是节选，不伪装拥有已经清理的内容。
- 相同物理文件可去重，但逻辑归属、授权和引用分别记录，不能因为一方删除就破坏其他有效引用。

### 8.2 图片

- 支持本地和远程图片服务，允许自动切换。
- 应用设置默认服务、备用顺序和切换场景；图片服务切换不改变全局对话主模型。
- 记录实际远程费用，检查已有执行结果以减少重复生成。
- 生成后只做文件、尺寸、完整性等基础检查，不额外调用主模型看成品验收。
- 技术失败可按任务修复规则处理；画面不满意由用户反馈后继续修改。
- 理解修图要求时查看输入原图不受成品免验收规则影响。
- 范围包括生图、修图、抠图、擦除、拼图、基础变换、网络图片和网页截图等，具体模型清单未定。

### 8.3 文档

- Word、PPT、PDF 等生成以自由设计为主，由模型编写生成代码，在本地 Docker 执行，不强制固定模板。
- 保存代码、输入、素材与产物之间的关系，支持后续修改。
- 用户委托制作文档，默认先给内容结构、页数或章节、版式和配图方案，由创建者确认后制作。
- 用户明确说直接做时可跳过大纲确认；反馈集中处理，不逐页反复询问。
- 自主参与中确有必要生成文档时，自行思考与规划，不询问大纲。
- 原件保留，文件完整性、溢出等基础检查尽量由程序完成。
- 阅读笔记、页码索引、转换、PDF 操作和翻译纳入文档能力；具体操作范围与格式清单在详细设计中列出。

### 8.4 计算与学习

- 简单计算优先主模型解答结合本地计算核对。
- 复杂推导、条件多或有疑点时，可另调用同一个主模型独立复核，不固定每题增加一次调用。
- 不将本地数值计算通过当成推导必然正确。
- Python 在同一任务内保留变量和加载数据；不同任务状态隔离。
- 任务结束或闲置超时后释放环境，文件和代码按规则保留；闲置时间可调。

### 8.5 视频

- 支持视频下载与总结，采用字幕/转写加按需画面分析。
- 下载、字幕提取、语音转写、场景分析、抽帧、时间索引和缓存放在本地处理。
- 本地小模型辅助选择相关片段，主模型生成总结和回答追问。
- 主模型为远程服务时，相关字幕及所选画面会发往该服务；不能宣称全程本地，默认不上传整段视频。
- 记录实际分析范围，不将抽样描述成逐帧看完整段。
- 具体平台、格式和限制需要详细设计与实际兼容性确认，不承诺任意链接都可处理。

## 9. 用量、权限、插件和更新

### 9.1 用量

- 统计并支持可配置累计限额：普通用户统一默认值、个人覆盖、不限，以及独立公共额度。
- 自主任务使用机器人公共用量，不扣触发普通用户的个人额度，保留触发原因和来源群。
- 模型 token、远程图片费用、本地资源分别展示，不做虚假统一折算。
- 不把未知用量显示成零，不把本地复用冒充供应商缓存命中。
- 默认额度、周期等具体数值尚未确认；共享执行费用分配等细则在详细设计中明确。

### 9.2 自主权限

- 尽量开放自主执行和调优能力，应用可逐项控制开放范围。
- 明确锁定的规则由管理员控制；默认保留此前确定的全局主模型、额度上限和权限控制方式。
- 允许的自动设置修改记录原因和前后值，提供可行的恢复入口。
- 机器人使用范围可在应用切换为全部开放或仅指定用户/群，并分别设置群内使用、记忆与主动发言。

### 9.3 扩展和兼容

- 支持第三方 AstrBot 插件，不局限于 12 类内置能力。
- 允许机器人自主查找、安装、启用新插件、技能和需要的依赖。
- 记录来源、安装目的与改动，提供停用、卸载和可行的恢复入口。
- 新增扩展与更新分开：已有软件、插件及公共依赖的升级仍由管理员决定。
- 分级显示完整接入、基础兼容、需要适配；安装成功不等于完整兼容。
- 普通插件尽量直接支持，接管核心、模型、记忆、发送等能力的插件单独适配。
- 需要适配的插件保持停用，说明原因并报告管理员，避免零散补丁不断叠加。
- 技能、网页、文件和普通发言的来源需要保留；扩展不能通过人格变化自行覆盖明确锁定的规则。

### 9.4 更新和备份

- 软件与插件发现更新只提示，管理员点击后才下载、安装，不自动更新。
- 运行任务时不直接强制重启。
- 自动备份加手动备份；定期保存关键数据，重要配置变更前保留恢复点。
- 备份重点为配置、记忆、人格版本、任务记录和重要文件；模型、可重新下载依赖和临时缓存可排除。
- 恢复数据不重新激活已中断任务。
- 备份位置、频率、保留代数、加密和恢复一致性方案尚待技术设计。

## 10. UI 已确认方向

- 参考桌面版 ChatGPT 的布局与交互感觉，采用暗色主题。
- 深灰背景、清晰的层次、柔和浅色正文，左侧可收起导航，中央大内容区。
- 默认首页为信息丰富的运行仪表盘，不默认进入聊天页。
- 首页覆盖连接与模型、任务队列、用量趋势、本地资源、人格成长缩略图、活动记录。
- 模块可拖动、调整大小、隐藏、恢复默认；两个入口共用本机布局。
- 隐藏模块只改变显示，不停用对应能力。
