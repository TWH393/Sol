# Sol 工具能力升级

本批按用户逐项确认的方案实现。人物、场景一致性继续待定。仅进行源码静态编译、JavaScript语法检查和Docker镜像构建，没有启动Sol/QQ、发送消息或调用模型验收。所有可用状态均为配置/实现说明，不代表账号权限或端到端行为已经实测。

## 统一执行架构

- GPT、DeepSeek、Gemini继续走同一模型网关。Sol自己提供文件检索、Docker、Skills、MCP和公开网页浏览，不要求服务商提供同名原生能力。
- 模型页和功能中心共用“工具能力与执行方式”，显示可用/需要配置/已关闭、实际后端、具体原因；支持适用功能的自动/本地/原生选择。原生权限和费用仍取决于账号和接口。
- 普通聊天仅保留人格、必要规则和短能力目录。执行任务时再补充任务规则和工具参数；每个新任务重新按需加载，旧任务说明不进入聊天历史。
- 小模型一次筛选话题、工具分类和记忆，与收消息等待重叠。不等待未完成的预处理；非合并消息最多等待2秒。不可用时使用确定性记忆检索和工具目录，由大模型补查，不阻断定向聊天。
- 小模型请求失败后有30秒冷却，避免每条消息重复撞不可用服务；后台抽取仍保留待处理资料，恢复后可以继续。没有增加每轮输入Token硬预算。

## Docker Python、Shell与依赖

- 同一任务共用一个容器和`/work/input`、`/work/output`；Python会话保留变量。Shell/技能共用文件，Shell进程本身不跨调用存活。
- 新增`run_shell`和`install_packages`，支持pip/apt/npm。包安装只修改任务Docker，不安装进Sol主进程或用户Windows环境。
- 常用镜像预装NumPy/Pandas/Matplotlib/SymPy/SciPy、Office与PDF库、OCR、中文字体、FFmpeg、LibreOffice、Pandoc、压缩、Git/Node/Chromium等。额外依赖可自主补装。
- 镜像按Dockerfile/执行协议内容生成版本标签，首用可自动构建；功能中心可提前准备。开发交付用`scripts/build_tools.py`仅构建镜像，不启动任务。
- 缓存按机器人、会话和创建者隔离；输入重名时有`input-manifest.json`按文件ID定位。模型代码不挂载主机工作区、账号或Docker控制socket。
- 当前每任务3GB内存、2CPU、160进程；文件限额沿用统一文件库。执行超时停止任务容器，不在后台继续跑同一段代码。重启只回收有匹配所有权标签的本项目容器，不恢复任务。
- 需要安装时模型可以自主安装，但不会因缺包自动重跑一整段可能已经执行过的代码；返回包名和失败步骤，继续修复对应部分。

## 文件输入、检索、OCR与笔记

- 单独上传文件先保存和确认收到，不立刻启动大模型做全文总结；后台建立本地索引。
- 正文索引覆盖PDF页、Word段落/表格、PPT幻灯片、Excel工作表/行与文本行。检索始终关联当前有效文件和权限，不只搜文件名。
- 新增`search_documents`，返回文件ID、位置、摘录和来源内容哈希；多文件可对照，指定文件的限制在SQL排名之前应用。
- 扫描件不在后台盲目OCR；需要时用`ocr_document`在Docker按页识别并保存可复用文字。原图、精确数字和公式仍可另行核对。
- 索引随原件状态清理，新内容哈希建立新索引。阅读笔记继续沿用`save_note`和原有来源页码证据规则。

## 生图与编辑

- 沿用已经配置的本地/远程/原生绘图后端；当前模型在正常规划中优化实际提示词，不另开一次模型调用仅为润色。
- 保留主体、数量、动作、原文和用户明确要求，按风格补构图、光线和细节。任务输入保留原请求，产物元数据保留实际提示词与后端。
- 图片编辑仍要求实际原图，选区擦除要求遮罩；长图、菜单、表格、公式走Docker真实字体排版。发送失败继续使用文件库重发，不重画。
- 本批没有添加人物卡、场景卡或参考图一致性流程，也没有承诺更换成尚未配置的新绘图模型。

## Skills

- 可先读已安装技能，自主搜索和安装公开仓库；支持GitHub仓库、tree子目录和SKILL.md链接。重复安装复用现有记录。
- 技能说明和参数只在需要时读取；新增补充资源读取和`run_skill`。脚本/模板打包传入任务Docker，Python/Shell/JS脚本可以执行，依赖在容器内安装。
- 同任务技能依赖准备成功后留标记，不每次重新安装。公开通用技能可复用，私有输入文件仍遵守原来的文件权限。
- “已安装技能”不等于所有任意脚本运行时已经验收；平台专用脚本、未声明依赖、需要账号的服务可能仍返回具体失败，需要模型修复或换方案。
- 既有AstrBot插件更新/依赖兼容规则保留，不把第三方插件脚本偷偷装进主进程来冒充技能执行。

## MCP

- 新增Sol自己的MCP客户端：`list_mcp_tools`、`connect_mcp`、`call_mcp`。模型切换不删除服务配置。
- 支持公开HTTPS Streamable HTTP服务；模型可自主寻找并接入无需登录的公开服务。已有服务的地址、凭据和使用范围不会被自动覆盖。
- 服务目录缓存，先返回简短工具摘要，指定工具后再加载完整参数。调用验证参数和授权工具列表；普通工具不自动当作只读操作并行。
- 管理员可以在应用配置Bearer凭据和使用范围，凭据不回显；更换地址时清除旧地址的继承凭据。需要额外登录或不兼容协议时明确说明，不假装连接成功。
- 本批没有实现任意本机stdio服务器、旧SSE传输或自动OAuth登录。MCP图片/二进制资源进入统一文件库，不把整段Base64当模型文字输入。

## 公开浏览器

- 新增模型无关`browse_public`，支持打开、读取、公开搜索框、点击、滚动、截图和公开下载。每个任务独立匿名会话，不读取个人浏览器标签、账号或历史。
- 页面正文可按偏移继续读，元素ref属于当前快照，页面变化后不能复用旧ref乱点。
- 需要登录或人机验证时停止该页面并说明无法读取，可以继续找公开替代来源；不弹出登录窗口、不保存登录账号。
- 页面内容、技能说明和MCP结果都是资料，不能更改Sol固定权限。既有原生电脑工具路径也保留不登录的边界。

## 并行与复用

- 同轮全部是已知只读操作时并行执行独立查询；混有修改/生成/发送或未知第三方操作时保留顺序。
- 相同只读调用在同任务合并在途工作并复用结果，不重读同一资料。搜索、读取仍走统一任务步骤、权限、模型用量路径。
- 不同人的消息不合并，后来的消息不修改前面的任务。历史读取尊重本轮上下文游标，显式协作仍要求创建者授权。

## 图片复用

- 上传ID缓存按服务地址、凭据和图片内容区分，兼容服务的并发重复上传合并；换到其他服务商重新上传。
- 服务商明确返回文件过期/不存在时，清除对应缓存并重新上传一次；不对普通额度/网络失败自动重试整轮模型调用。Files接口不兼容时可使用直接图片输入。
- 新增`remember_image`保存客观描述、清楚文字与不确定处，并核对本轮确实包含原图。旧版直接把整段回答写入的缓存不再当作可靠识图笔记。
- 保存笔记后，本任务后续请求可用笔记替换已读像素；问到未覆盖细节时仍能重新`view_image`。来源、笔记/原图模式继续在文件的模型输入记录里显示。
- 上传复用不等于图片输入免Token；服务商重复看图仍可能计费。

## 由用户验收（未代执行）

1. 小模型关闭时私聊“你好”，再请求搜索/读取文档，确认大模型仍能调用工具。
2. “用Python算1到100的平方和并生成折线图”，再用Shell转成PDF，核对同任务文件。
3. 发PDF但不附问题，确认先收件；随后按文件内容找一句话，核对页码和原文。
4. 扫描PDF选一页OCR，随后追问同页文字，观察是否复用索引。
5. 选一个公开技能，读取说明并执行脚本，核对Docker依赖和产物。
6. 连接一个无需账号的公开MCP，先看目录再调用具体工具；切换模型后配置仍在。
7. 打开公开网站搜索或下载；再尝试必须登录的页面，确认只说明限制、不要求登录。
8. 同一任务重复查询相同资料，查看步骤/活动记录的复用；含写操作的调用检查顺序。
9. 同一张图片保存笔记后追问已识别内容，再问小字细节，检查笔记/原图输入记录。
10. 功能中心选择本地/原生，关闭某一能力，检查对应工具是否被停用；原生方式需账号实际支持。
