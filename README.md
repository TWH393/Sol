# Sol

以 AstrBot 为内部引擎的本机机器人工作台。C# / WPF 提供原生桌面，内部 Python 引擎与浏览器管理页使用同一套服务和数据。默认暖白与陶土橙外观，顶部可切换暗色；选择自动保存，并同步对应Logo。

当前版本：0.2.0 开发预览版。桌面WebView2承载完整管理页面，与浏览器共用核心和数据。本机迁移版本已由用户确认可以使用；全新电脑的安装流程尚未验收。目前提供源码与构建脚本，**没有正式的一键安装包 `Sol-Setup.exe`**。

## 唯一工作目录与发布边界

作者本机后续开发固定在 `D:\SOL`，其他使用者可以选择自己的克隆目录，脚本按项目根目录定位。打开根目录 `Sol.sln`。`.venv` 优先由目录内 `toolchain/python` 创建，也支持标准Python 3.12；核心依赖锁定在 `requirements.lock.txt`，不使用旧AstrBot启动器的Python。系统仍需Windows、Visual Studio/.NET SDK、CMake及Docker Desktop等开发工具。

源码、资源制作说明与脚本可上传GitHub；`state`（个人数据和凭据）、`toolchain`、`runtime`（模型/浏览器/绘图环境）、`.venv`、`build`、`dist`和`.migration`均被Git排除。个人运行目录不能直接整目录打成公开安装包。后续发布由构建脚本生成干净程序，再按需准备模型，使用者自行登录自己的账号并填写密钥。

## 安装和启动

1. 本机程序位置为 `build/Sol/Sol.exe`。开发版可从根目录运行`启动Sol.cmd`；从GitHub下载源码后，需要先完成源码安装。
2. 从源码安装：运行 `安装Sol.cmd`。开发构建需要 .NET 10 SDK、Python 3.12；脚本准备功能依赖、构建私有引擎并创建快捷方式。发布后运行不依赖开发用 `.venv` 或机器上的 .NET SDK。
3. 在“设置与运行环境 → 账号接入”填写机器人QQ与管理员QQ，通过Sol原生接入扫码登录，不需要LLBot授权Token。首次使用需要本机安装官方Windows QQ，以准备独立客户端。
4. 在“模型与思考”添加主模型；GPT 套餐可由应用发起登录，其他 API Key 保存在本机凭据库。
5. 保存接入配置后启动 QQ 服务，完成本人的账号扫码；需要时重启内部核心使账号配置生效。

Visual Studio 打开根目录 `Sol.sln`，主项目为 `desktop/Sol.Desktop`。当前本机版继续使用项目 `state/`，不是已经完成的跨机器安装包。详细边界见 [Sol桌面架构](docs/Sol桌面架构.md)。

浏览器入口默认 `http://127.0.0.1:24760/`，HTTP后台仅允许本机访问。QQ默认使用Sol原生独立客户端；Docker用于任务执行。保留的旧接入兼容代码不表示必须安装NapCat、LLBot或独立AstrBot启动器。

关闭窗口收进托盘；在托盘选择“退出并停止机器人”才退出。Windows 登录自启动可在设置中关闭。

本地图片资源默认位于项目 `runtime/images`，ComfyUI位于其下 `ComfyUI`。图片编辑、抠图和ComfyUI环境各自独立，路径可在功能中心修改。模型与环境仅作为本机资源，不进入源码包；缺失时由资源准备脚本安装，不把下载或构建成功称为生图验收成功。

## 结构

```text
Sol.sln               Visual Studio 解决方案
desktop/Sol.Desktop/  C# 原生窗口、托盘、自启动、认证API客户端和引擎生命周期
companion/
  application.py       服务装配与生命周期
  config.py            唯一配置来源、加密凭据
  storage.py           SQLite记录、全文索引、事件
  memory.py            来源记忆、本地整理、启动人格复盘
  models.py            统一模型入口、思考强度、用量
  tasks.py             分步资源调度、授权、中断
  files.py             产物、归属、引用与清理
  agent.py             话题、连续消息、工具执行
  runtime.py           AstrBot适配、服务管理、统一发送
  extensions.py        第三方扩展与兼容分级
  backup.py            自动/手动备份与恢复
  api.py               本机接口；无人工代发聊天接口
  engine.py            由C#启动的无界面内部引擎
  tools/               代码、文档、媒体、网络、控制工具
  workers/             隔离的Python、图片、视频工作进程
  bridge_plugin/       唯一的AstrBot整合入口
  web/                 浏览器完整管理页
vendor/                AstrBot源码、图像算法、GPT套餐桥
scripts/               安装、资源准备和打包
state/                 运行数据、凭据、资源与备份（不入源码包）
```

## 已编码的主要流程

- 自然聊天、同一发言人短窗口内补充合并；后续轮次独立处理，按引用与话题接群聊。
- 所有记忆统一管理，保留身份、来源和证据；公共知识复用，个人私聊内容按已定规则使用。
- 本地小模型幕后分类与整理；最终对话使用统一主模型。
- 人格仅核心启动时复盘，无新经历或实质变化不生成成长记录；版本和曲线可查看、恢复。
- 每模型固定/自动思考强度；软件用户限额与公共额度分开，未知用量不填成零。
- 任务分步排队，用户任务优先，同任务协作需要创建者授权。
- 普通执行任务在退出或掉线后中断，不在重启后自动续跑；未来提醒单独持久化，一次性与周期错过补发可分别设置。
- 本地/远程绘图切换；抠图、修图、拼图与基础变换；成品不追加云端视觉验收。
- 文档先确认大纲，自主必要产物和明确要求直接制作时跳过；生成代码在 Docker 执行。
- PDF 读取、渲染、操作、翻译和来源笔记；图片与已有文件可继续使用。
- Python 同任务保留变量，任务结束或闲置释放；简单数值本地核对，复杂解答按需独立复核。
- 视频字幕优先、本地转写、按需画面，保留时间索引；远程主模型仍会收到相关文字和所选图像。
- 扩展可自主安装，已有公共依赖升级仍需管理员决定；兼容级别明确展示。
- 可调整仪表盘、只读会话、文件与任务中心、记忆、人格、模型、用量、功能、插件、活动和设置页面。

## 数据与中断语义

- 原始消息、记忆、任务、文件、人格和用量分别建表，通过 ID 关联。
- 删除记忆不连带删除原始消息或文件，不设禁止重新学习标记。
- 文件收藏和引用决定保留，清理不伪装成文件仍存在。
- 备份默认排除凭据、模型与可重新下载缓存；恢复不复活任务。
- 源码包不包含 `state/`、旧机器人配置、登录状态或 API Key。
